FocusFlow settings

Strict mode is always on: a page opens only when it is judged to be study or tech content.

  1. Read the page. Title, description, OpenGraph/JSON-LD tags and headings. For YouTube: the video's category, description and tags, fetched from YouTube.
  2. Look the site up. FocusFlow fetches the site's home page once to learn what the site is about.
  3. Ask the AI. A thinking model that you run (on your computer, your free Hugging Face Space or any server) decides study or block. Thinking is always on.
  4. Learn and get faster. Every answer is remembered, videos on screen and the link under your mouse are judged before you click, and the offline model learns from the AI for when it can't be reached. Only pages are blocked, not whole sites, unless a site has shown nothing but distractions.

Set up Ollama (2 minutes)
  1. Install Ollama from ollama.com/download.
  2. Download the thinking model: ollama pull qwen3:4b (≈2.5 GB, runs fully on a 4 GB GPU). On Windows, scripts\windows\setup-ollama.cmd does all of this and tunes Ollama for speed.
  3. Keep Ollama running. If Test says 403, allow extensions and restart Ollama: OLLAMA_ORIGINS=chrome-extension://*,moz-extension://*
Set up a free Hugging Face Space
  1. Create a new Docker Space (free CPU basic) at huggingface.co/new-space.
  2. Upload the two files from this repo's hf-space/ folder.
  3. Optional: add a secret LLAMA_API_KEY and paste the same value as the access token below.
  4. Use https://<your-username>-<space-name>.hf.space/v1 as the server URL. Free Spaces have 2 CPUs: a new page takes ~10–30 s, which pre-judging mostly hides.
Run it on your own free server (faster than a Space)
  1. Oracle Cloud's Always Free tier gives a VM with 4 CPUs and 24 GB RAM, free with no usage limit.
  2. On the VM: docker build -t focusflow-llm hf-space && docker run -d --restart=always -p 7860:7860 -e LLAMA_API_KEY=<secret> focusflow-llm
  3. Open port 7860 in the VM's firewall, then use http://<vm-ip>:7860/v1 and your secret as the access token.

Thinking is always on. If the server can't be reached, the offline model decides (strict) until it's back.
